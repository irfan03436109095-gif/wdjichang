机场测速单连接慢、多连接快怎么看？先做两组基线

王牌飞行员2026-09-28— 次阅读
使用教程

测速工具显示带宽很高，单个下载却很慢，并不一定代表节点“虚标”。单连接和并行连接施加的负载不同，应该分开记录，再决定这条线路是否适合自己的实际任务。

先理解两类结果

单连接测试只建立一条传输路径，更容易暴露单流吞吐、远端限速和路径抖动。并行测试会同时发起多条传输，汇总速度可能更高，也会占用更多连接和流量。curl 官方手册说明，默认 URL 按顺序传输；启用 --parallel 后会并行处理，--parallel-max 用于限制同时传输的数量。

这两类测试没有谁天然更“真实”。下载单个文件、远程终端更接近单连接；同时打开多个网页资源或多任务下载，更接近并行情形。

用同一批小文件做两组基线

准备三个自己有权下载、大小相近的测试文件，先记录直连，再依次测试候选节点。

顺序组：

curl -o NUL -w "time=%{time_total} speed=%{speed_download}\n" URL1 URL2 URL3

并行组：

curl --parallel --parallel-max 3 -o NUL URL1 -o NUL URL2 -o NUL URL3

Windows PowerShell 中也可把 NUL 换成 $null 对应的安全输出方式；关键是不要把测试文件反复写入磁盘。每组至少交替做三轮，固定设备、网络、目标文件和时间窗口，并核对机场后台流量余额。

怎样解读差异

  • 单连接和并行都稳定：线路更容易覆盖不同任务。
  • 单连接慢、并行明显快：总带宽可能够用，但单个长连接体验一般。
  • 并行时错误增多：并发连接可能放大抖动或触发目标服务器限制。
  • 两组都忽快忽慢：继续观察晚高峰、丢包和入口负载，不要只保留最高值。

并行测试会增加请求数量，不能对不允许压测的网站使用，也不应为了跑出高分无限提高并发。

机场推荐的验收标准

根据自己的主要任务给两组结果分配权重。经常下载单文件，应把单连接稳定性放在前面；多网页、多设备使用者再关注适度并行表现。最终还要用真实网页、会议或下载任务验收，不能只用汇总峰值给机场推荐下结论。

来源：curl 官方手册：顺序传输、--parallel 与 --parallel-max。
